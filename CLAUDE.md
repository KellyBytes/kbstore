## Commands

```bash
npm run dev              # Next.js dev server
npm run build            # Production build
npm run lint             # ESLint (flat config, eslint-config-next)
npm test                 # Jest (ts-jest preset)
npx jest tests/paypal.test.ts            # Single test file
npx jest -t "generates token from paypal" # Single test by name
npm run email            # React Email preview server on :3001 (copies .env into node_modules/react-email)

npx prisma migrate dev --name <name>     # Create/apply a migration
npx prisma generate                      # Regenerate client (also runs on postinstall)
npx prisma db seed                       # Seed via `tsx db/seed.ts` (configured in prisma.config.ts)
```

Tests in `tests/` hit the real PayPal sandbox API (`jest.setup.ts` loads `.env` via `dotenv/config`), so they require `PAYPAL_CLIENT_ID` and `PAYPAL_APP_SECRET` to be set (`PAYPAL_API_URL` defaults to the sandbox).

## Stack

Next.js 16 App Router (React 19), TypeScript, Tailwind v4 + shadcn/ui (`components/ui` is generated by shadcn — avoid hand-editing), NextAuth v5 beta, Prisma 7 on Neon Postgres, Zod v4, react-hook-form, Stripe, PayPal (REST via `fetch`), Uploadthing, Resend + React Email.

## Architecture

### Data flow
Pages are mostly Server Components that call **Server Actions** in `lib/actions/*.actions.ts` (`'use server'`) directly for both reads and mutations. There is no REST layer except `app/api/` (NextAuth handlers, Uploadthing, Stripe webhook). Mutating actions follow the pattern: validate with a Zod schema from `lib/validators.ts` → Prisma call → `revalidatePath(...)` → return `{ success: boolean, message: string }`, catching errors with `formatError()` from `lib/utils.ts`. Client forms surface these via `toastSuccess`/`toastError`.

Types in `types/index.ts` are derived from the Zod schemas (`z.infer<...>`), so changing a validator changes the app-wide type.

### Prisma
- Generator outputs to `lib/generated/prisma` (gitignored) — import from `@/lib/generated/prisma/client`, not `@prisma/client`.
- `db/prisma.ts` exports a single client using the Neon serverless adapter (WebSocket via `ws`) and a `$extends` **result extension that converts all `Decimal` money/rating fields to strings** (product, cart, order, orderItem). Code throughout treats prices as strings; use `round2()` / `Number()` for arithmetic. Query results are passed through `convertToPlainObject()` before returning to client components.
- `Order.shippingAddress` / `paymentResult` and `Cart.items` are JSON columns; cast them to the types in `types/index.ts`.

### Auth (two-file NextAuth split)
- `auth.config.ts` — edge-safe config (no Prisma). Its `authorized` callback protects routes via a regex list and **creates the `sessionCartId` cookie** for guest carts.
- `proxy.ts` — Next 16's middleware equivalent; uses only `auth.config.ts`.
- `auth.ts` — full config: Credentials provider (bcrypt-ts-edge), Prisma adapter, JWT strategy. The `jwt` callback puts `role` on the token, replaces `NO_NAME` users' names with their email prefix, and on sign-in **merges the guest cart** (cart with matching `sessionCartId`) into the user's cart.
- Admin authorization is not in the proxy: each admin page calls `requireAdmin()` from `lib/auth-guard.ts`, which redirects to `/unauthorized`.
- Session type augmentation lives in `types/next-auth.d.ts`.

### Cart & checkout
Cart is a DB row keyed by `sessionCartId` (cookie) and optionally `userId`; prices are recalculated server-side in `cart.actions.ts` (`calcPrice`: free shipping over $100, 5% tax). Checkout steps are separate routes in `app/(root)`: `cart` → `shipping-address` → `payment-method` → `place-order` → `order/[id]`.

### Payments
All payment methods converge on `updateOrderToPaid()` in `order.actions.ts`, which decrements stock and marks the order paid in a `$transaction`, then sends the receipt email (`email/purchase-receipt.tsx` via Resend).
- PayPal: `lib/paypal.ts` (token + create/capture order) used by order actions.
- Stripe: PaymentIntent created on the order page; `app/api/webhooks/stripe/route.ts` handles `charge.succeeded` using `metadata.orderId`.
- Cash on delivery: admin marks paid/delivered via `updateOrderToPaidCOD` / `deliverOrder`.

### Configuration
App-level constants and defaults (page size, payment methods, user roles, form default values) live in `lib/constants/index.ts` and are overridable via env vars (`PAGE_SIZE`, `PAYMENT_METHODS`, `DEFAULT_PAYMENT_METHOD`, `USER_ROLES`, `LATEST_PRODUCTS_LIMIT`, `NEXT_PUBLIC_SERVER_URL`, `SENDER_EMAIL`, ...).

### Route groups
`app/(auth)` sign-in/up, `app/(root)` storefront + checkout, `app/user` account area, `app/admin` dashboard (overview charts via Recharts, products/orders/users CRUD).
